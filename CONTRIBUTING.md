# Contributing — Early Source Drop Draft

Thank you for taking the time to inspect Human Minority.

Human Minority is currently in **early development**. The first public repository is intended for transparency, technical feedback and early testing rather than unrestricted upstream code contribution.

## What is welcome

At the Early Source Drop stage, the project welcomes:

- bug reports against the published code;
- reproducible test failures;
- documentation corrections;
- security reports through the private security-reporting path;
- architecture and API feedback;
- reports of portability, packaging or dependency problems;
- questions about the documented trust model.

## External code pull requests

External code contributions are **not accepted/incorporated yet** unless the project explicitly changes this policy.

This is an upstream contribution-policy decision, not a restriction on license-compliant use, forks or modifications of the published software. Those rights are governed by the shipped software license.

The restriction exists because the project has not yet finalized contributor rights/relicensing terms for a source-available commercial product. The project will not silently assume that a DCO, generic GitHub contribution or issue comment grants broader relicensing rights.

## Before reporting a bug

Please include, where relevant:

- exact Human Minority public revision/tag;
- Python/runtime/OS version;
- smallest reproducible input;
- expected behavior;
- actual behavior;
- full error code/message without secrets;
- whether the issue reproduces from a clean environment.

Do not attach private repositories, secrets, credentials or customer data to public issues.

## Security issues

Do not publish exploitable security details in a normal issue. Follow the repository's `SECURITY.md` instructions.

## Scope

The public Early Source Drop is intentionally smaller than private upstream development. A report that a private/planned feature is missing is not automatically a bug in the public artifact.
